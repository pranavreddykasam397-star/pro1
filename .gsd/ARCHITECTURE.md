## Overview

Heritage Restaurant is a full-stack digital dining and ordering platform. It provides a customer storefront for browsing an authentic Indian menu, playing interactive mini-games for discounts, placing orders with UPI QR payments, and tracking order history with a PIN. It also includes an administrative portal for restaurant staff to manage menu items, approve incoming orders, inspect payment receipts, and review daily sales analytics.

## Data Flow

1. **Client Boot & Synchronization:**
   * Client issues `GET /api/data` on load to fetch menu items, daily specials, and UPI settings.
   * Client initiates a 5-second polling interval (`setInterval`) to keep order status and menu sync live.
2. **Order Placement & Payment:**
   * Customer selects items $\rightarrow$ Cart computes subtotal and applies any game discount.
   * Customer initiates checkout $\rightarrow$ Enters/creates Customer PIN and phone number.
   * Customer scans UPI QR code $\rightarrow$ Optionally uploads transaction screenshot encoded as base64/URL.
   * Client posts to `POST /api/orders` $\rightarrow$ Server inserts record into MongoDB with status `PENDING`.
3. **Owner Processing:**
   * Admin logs in via `/api/auth/login` (or 2FA OTP via Textbelt) and receives a signed JWT (`x-admin-token`).
   * Admin inspects incoming pending orders and payment screenshot $\rightarrow$ Dispatches `PATCH /api/admin/orders/:id` to mark `CONFIRMED` or `REJECTED`.
   * End of day: System calculates cumulative revenue and writes to `DailySummary`.

## Technical Debt & Observations

- [ ] **Monolithic Files:** `src/App.jsx` (~1,374 lines) and `backend/server.js` (~811 lines) combine routing, state, validation, and presentation in single files.
- [ ] **Lack of Type Safety:** Written entirely in vanilla JavaScript; no compile-time payload guarantees between frontend and backend.
- [ ] **Data Validation:** Input parsing is manual (`parseInteger`, ad-hoc string checks) rather than using a schema validation engine like Zod.
- [ ] **High Network Overhead:** Client relies on 5-second polling rather than WebSockets, Server-Sent Events (SSE), or Webhooks.
- [ ] **Global CSS:** ~1,200 lines of custom CSS in `globals.css` without scoped styles or atomic utilities.
- [ ] **Secrets & Security:** Hardcoded fallback tokens (`super_secret_admin_token_123`) present in code if environment variables are omitted.
